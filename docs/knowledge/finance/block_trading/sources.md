## 一、 第一性原理透视：大宗交易数据的本质与流转链条

大宗交易（Block Trading）是投资者在常规竞价撮合系统之外，通过交易所专用系统进行的单笔大额协议交易。其数据流转遵循严格的法定义务与物理闭环：

```
[买卖双方协议撮合/意向申报] 
        ↓ 
[交易所专设大宗交易系统(收盘后15:00~15:30申报/盘中意向申报)] 
        ↓ 
[交易所主机清算与席位核算] (物理与法定唯一源头)
        ↓
  ┌─────┴────────────────────────────────────────┐
  ↓                                              ↓
【Level 0: 法定披露源（三大交易所官网）】       【Level 1: 登记结算机构（中登公司 CSDC）】
- 15:30~16:00 准时向全市场法定公开               - 负责账户交收与股权过户，非即时交易公开明细披露端
- 法律效力最高、零二手加工延时与失真
  │
  ├──────────────────────────────────────────────┐
  ↓                                              ↓
【Level 2: 一级金融信息服务商（东财/同花顺）】   【Level 3: 开源自动化数据接口（AkShare等）】
- 自动化同步交易所数据，清洗合并三市，增加衍生指标  - 封装 L0/L2 的 RESTful/JSON 接口，提供 Python 开箱即用
```

### 核心要素标准（全、准、准时）：
1. **准（真实性/法律证据级）**：必须以**上海证券交易所（SSE）、深圳证券交易所（SZSE）、北京证券交易所（BSE）**一线披露为基准。
2. **准时（时效性）**：交易所每日 15:30 申报关闭后进行业务清算，在 **15:30 ~ 16:00 之间完成官网首发**。
3. **全（完整性）**：覆盖沪市主板+科创板、深市主板+创业板、北交所全量成交（包括证券代码、成交价、成交量、成交金额、买方营业部/席位、卖方营业部/席位、折溢价率）。

## 二、 核心法定权威源（Level 0）

### 1. 上海证券交易所（SSE）
* **官网栏目**：上海证券交易所官方网站 - 披露 - 交易公开信息 - 大宗交易
* **官方 Web 地址**：[http://www.sse.com.cn/disclosure/diclosure/block/](http://www.sse.com.cn/disclosure/diclosure/block/)
* **法定依据**：依据《中华人民共和国证券法》第四十七条及《上海证券交易所交易规则》《上海证券交易所大宗交易实施细则》，上交所作为一线监管法定主体，在每个交易日结束后统一编制并向社会公开当日大宗交易成交明细，具有法定唯一真实性。
* **数据抓取底层接口（REST/JSONP）**：
  * **请求方法**：`GET`
  * **请求头要求**：必须携带 `Referer: http://www.sse.com.cn/`（防盗链校验）
  * **URL 范例**：
    ```
    http://query.sse.com.cn/commonQuery.do?isPagination=true&sqlId=COMMON_SSE_XXPL_JYGKXX_DZJY_L&pageHelp.pageSize=100&pageHelp.pageNo=1&startDate=YYYY-MM-DD&endDate=YYYY-MM-DD
    ```
  * **关键字段说明**：
    - `SECURITY_CODE`：证券代码（如 600519）
    - `SECURITY_ABBR`：证券简称（如 贵州茅台）
    - `TRADE_PRICE`：成交价格（元）
    - `TRADE_QTY`：成交数量（股/份）
    - `TRADE_AMOUNT`：成交金额（万元）
    - `BUY_BRANCH`：买方营业部/交易单元席位
    - `SELL_BRANCH`：卖方营业部/交易单元席位

### 2. 深圳证券交易所（SZSE）
* **官网栏目**：深圳证券交易所官方网站 - 市场数据 - 交易信息披露 - 大宗交易
* **官方 Web 地址**：[http://www.szse.cn/market/trend/block/index.html](http://www.szse.cn/market/trend/block/index.html)
* **法定依据**：依据《深圳证券交易所交易规则》《深圳证券交易所大宗交易实施细则》，深交所对其综合协议交易平台产生的大宗交易记录负有法定披露义务，收盘清算后公布。
* **数据抓取底层接口（JSON API）**：
  * **请求方法**：`GET`
  * **URL 范例**：
    ```
    http://www.szse.cn/api/report/exchange/onecode?showTitle=1&catalogId=1803&tab1PAGENO=1&selectDate=YYYY-MM-DD
    ```
  * **返回格式**：标准 JSON 结构，包含深市主板与创业板全量大宗成交席位明细。

### 3. 北京证券交易所（BSE）
* **官网栏目**：北京证券交易所官方网站 - 信息披露 - 交易公开信息 - 大宗交易
* **官方 Web 地址**：[https://www.bse.cn/disclosure/block_trading.html](https://www.bse.cn/disclosure/block_trading.html)
* **法定依据**：依据《北京证券交易所股票上市规则》《北京证券交易所交易规则》，负责北交所上市股票及转让标的盘后大宗成交发布。

## 三、 工程化高可用抓取与自动化方案（Level 2 & Level 3）

直连三大交易所虽然最原生，但维护成本偏高（需维护 3 套不同的翻页协议、字段格式与防爬策略）。在实际工程落地中，业界首选权威规范聚合源：

### 方案 A：Python 开源库 AkShare（推荐首选，零门槛开箱即用）
* **优势**：免申请 Token、无调用频次硬限制、字段做过严格规整、底层自动同步权威数据。
* **核心接口**：
  1. `ak.stock_dzjy_mrmx(symbol="A股", date="YYYYMMDD")`：获取指定交易日全市场（沪深北三市）大宗交易明细。
  2. `ak.stock_dzjy_mrtj(date="YYYYMMDD")`：获取指定交易日的大宗交易折溢价汇总与营业部交易统计。
* **实战调用代码**：
  ```python
  import akshare as ak

  # 获取 2026-09-24（或指定日期）全市场大宗交易成交记录
  df = ak.stock_dzjy_mrmx(symbol="A股", date="20260924")
  print(df[["证券代码", "证券简称", "成交价", "成交量", "成交额", "买方营业部", "卖方营业部", "折溢价率"]])
  ```

### 方案 B：东方财富网数据中心 RESTful 接口（轻量爬虫直连）
* **Web 展示页**：[https://data.eastmoney.com/dzjy/dzjy_mrmx.html](https://data.eastmoney.com/dzjy/dzjy_mrmx.html)
* **直接 REST API（JSONP/JSON）**：
  ```
  https://datacenter-web.eastmoney.com/api/qt/data/get?type=RPT_DATA_BLOCKTRADE&params=&p=1&ps=100&st=SECURITY_CODE&sr=1&var=
  ```
* **工程优势**：
  1. 沪深北三大交易所一次性统一输出；
  2. 自动计算折溢价率（相比当日收盘价的溢折价比例）；
  3. 支持按日期跨度批量拉取与分页。

## 四、 选型矩阵与工程实施建议

| 维度 | 方案一：交易所官网直连（L0） | 方案二：东方财富数据中心 API（L2） | 方案三：开源 AkShare 脚本（L3） |
| :--- | :--- | :--- | :--- |
| **权威合法性** | 极高（法定义务与法律证据级） | 高（权威合规公示） | 高（底层直连 L0/L2 验证） |
| **数据时效** | 最快（15:30~15:45 陆续发布） | 快（15:40~16:00 同步完成） | 快（与聚合接口一致） |
| **抓取维护成本** | 较高（需分别维护三所请求头/协议）| 低（单接口统一全市场数据） | 极低（Python 一行代码开箱即用） |
| **字段完备度** | 基础原始成交字段 | 完备（附带折溢价率、历史累计等） | 完备 |
| **推荐适用场景** | 司法取证、极端低延迟监控 | 生产级量化数据库日常定时 ETL | 策略回测、研究员即席分析、自动化脚本 |

### 工程抓取实践最佳准则：
- **触发时间**：交易日下午收盘后，建议将定时抓取任务定在 **16:05 ~ 16:15**，此时三家交易所清算披露完全就绪。
- **重试保障**：配置指数退避重试（16:05、16:10、16:20 各尝试一次），避免偶发清算延时。
- **校验对账**：采集完成后，对比记录笔数与各所公布的当日汇总笔数是否一致，防范漏单。
