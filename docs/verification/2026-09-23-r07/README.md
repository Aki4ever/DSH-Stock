## 二、逐条需求验收要点

### REQ-037 所有K线图默认副图为成交额
- K线面板首屏副图档位实测 `data-subplot="amt"`，渲染出的副图标题为「副图：成交额」。
- 当日分时面板（非K线图，用户裁决例外）实测为 `vol` + 「副图：成交量」。
- 5分K线（K线形态图）在未手动选过副图时自动取 `amt`，切回当日分时自动回到 `vol`。
- 用户手动选过副图后（`subplotTouched=true`），切换日线/周线颗粒度**不会**被强制改回默认 —— 实测切周线再切回日线后仍为「成交量」。

## 五、本轮发现并修复的缺陷（如实登记）

1. **卖点永不渲染（等级解析错误）**：前端用 `String(type).slice(3)` 取等级，`'buy1'.slice(3)` 得到 `'1'`（正确），但 `'sell1'.slice(3)` 得到 `'l1'` → `parseInt` 为 `NaN` → 所有卖点被判定为无效等级而**永不渲染**。改为按数字字符提取（`replace(/[^0-9]/g,'')`）后修复；R07 真机断言已覆盖（4 项卖点相关断言，修复前全部失败）。
2. **工具区 264px 过度裁剪**：初版固定高度取 264px，实测把整个「缠论图层」分组裁到可视区之外（需滚动才能看到）。改为 500px 后图层完整可见，同时保留「超出内部滚动」兜底。
3. **分组标题被换行拆散**：`.chart-tool-group` 初版允许组内换行，导致「缠论相关」标题留在上一行行尾、其控件落到下一行。改为整组 `nowrap`（窄屏断点允许换行）后行差为 0。

**关于 REQ-039 断言的修正**：原断言比较标题与控件的 `top` 差值。R07 交付时左面板默认隐藏（`hidden`），`getBoundingClientRect()` 对隐藏元素恒返回 0，于是 `0 - 0 = 0` 得到「行差 0.0px」——属**假通过**。R08 让左图默认可见（REQ-045）后暴露真实几何：标题 span 高 22.5px、分段控件高 37.4px、按钮高 30.9px，flex `align-items:center` 下**垂直中心线差为 0.00px、垂直重叠 22.5px、`flex-wrap:nowrap`**（左右面板数值完全相同），即视觉上严格同行，`top` 差只是元素高度不同所致、并非换行错位。故按「中心线对齐＋垂直重叠」修正口径。

重跑结果：R07 **41/41 PASS**、R06 **35/35 PASS**，控制台错误 0；报告副本 [browser-report-r08-regression.json](browser-report-r08-regression.json)。说明：两份验收报告原为未跟踪文件，回归重跑会覆盖 `browser-report.json`，故另存带 `-r08-regression` 后缀的副本留痕；R07 交付时的 39/39 结论仍以本文档第一节表格为准。

## R09 后的口径修订（2026-09-24，v5.4.0）

本脚本此前有 6 项失效，根因是产品把**左右两个独立副图控件合并成唯一的「幅图联动」控件**（`#chartSubPlotControlUnified`，文案「单点切换，分时与K线同步联动」），而脚本仍在查已不存在的 `#chartSubPlotControlLeft/Right`（→ `active=null`）。修订原则：**读现行真实控件 + 断言现行真实语义**，不删断言、不回头改产品。

| 原断言（R07 交付时） | 修订后 | 依据 |
| :--- | :--- | :--- |
| 查 `#chartSubPlotControlRight .seg-btn.active` 判断档位 | 改查 `#chartSubPlotControlUnified .seg-btn.active`，并新增「页面仅 1 个 `[data-subplot]` 控件容器」与「仅 1 个档位高亮」两项断言 | 控件已合并（`web/index.html`） |
| 「当日分时面板默认保持成交量」当作**独立档位**证据 | 拆成两项：①首屏沿用本维度默认档位（K线＝成交额／当日分时＝成交量，**如实登记二者与统一高亮在首屏的不一致**）；②**手动切换后两图联动一致** | 现行 `switchChartSubplot(sub, 'both')` 一次切换两图同步；分时默认值未变 |
| `switchChartSubplot('vol','right')` 只改右侧 | `switchChartSubplot('vol')` 后断言**左右两面板渲染一致** | 同上 |
| 「5分K线默认成交额／切回当日分时自动回到成交量」 | 改为「5分K线跟随统一档位渲染成交额」「切回当日分时仍与统一档位一致（联动不丢失）」 | 现行只有唯一档位，不存在「按图自动回到默认」 |

重跑结果：**44/44 PASS**（原 41 项 + 新增 3 项），控制台错误 0。
原始报告：[browser-report-r09-regression.json](browser-report-r09-regression.json)。

> **遗留观察项（需产品方决策，本批未擅自改语义）**：统一控件静态高亮为「成交额」，而当日分时面板在用户未手动选择前按其本维度默认渲染「成交量」——首屏未点选时两者不一致；点选任一档位后立即同步。是否统一首屏默认档位（一行改动：`panelDefaultSubplot` 恒返回 `'amt'`）或让高亮同时反映两图档位，已在 `docs/requirements.md` 的「R09 附表：REQ-037 口径修订」登记。
