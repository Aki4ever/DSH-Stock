# BUG-005 副图「总和」恒为 `--`、指数副图出现量纲错误的天文数字、不可得被当作 0

- **发现时间**：2026-09-24（R09 批次 REQ-046/047 真机验证过程中暴露）
- **状态**：已解决（本地技术验收：静态用例 + 真机 28/28 PASS）
- **影响面**：个股日K副图「总和」统计项；大盘指数 K 线副图的四维分布、副图刻度、辅助线交易面积
- **风险等级**：中（不中断渲染，但**对外展示错误数值**，违反「数据可溯源、不以推测值/0 冒充」的工程铁律）

## 1. 现象

### 1.1 「总和」恒为 `--`

个股日K副图（成交额档）表头显示 `总和: --`，而同一行的 `平均: 36.32亿`、`中位数: 31.77亿` 等均有值 —— 30 根样本的平均值 × 30 与页面左下角 `总成交额: 1098.74亿 (30个交易日)` 一致，说明总和**本来可得**，只是没显示出来。

### 1.2 指数副图出现量纲错误的天文数字

大盘指数 sh000001（全部K线）副图显示：

```
平均: 2447529.69亿  地量(最小): 1190899.23亿  天量(最大): 3943378.97亿  中位数: 2378699.41亿
副图刻度: 3943379.8亿
```

同期页面提示「当前来源未披露该指数成交额，副图不出数」—— 两段内容自相矛盾：提示说不披露，图却给出了 240 万亿亿级的数字。

### 1.3 「不可得」被当作 0

辅助线交易面积在整段区间**一段可用成交额都没有**时仍返回 `0.00亿`，与「面积为 0」这一截然不同的结论混为一谈。

## 2. 根因

1. **字段名误用（1.1）**：`computeWindowTotalAmount()` 返回的字段是 `totalAmountYi`，而副图表头与表格汇总读取的是 `windowAmount.totalYi`（不存在）→ `Number.isFinite(undefined) === false` → 恒走 `--` 分支。同一处死代码块 `subSumBadge` 也引用了该错误字段（且从未被渲染）。
2. **指数成交额口径被兜底估算值污染（1.2）**：`resolveKlineAmount()` 在来源缺少成交额时会用「均价 × 成交量」兜底；对**指数**而言，「指数点位 × 成分股成交量」与全市场成交额不是同一量纲（实测偏差数百至数千倍）。指数副图的四维分布、`maxAmount` 刻度、交易面积原先都建立在 `withResolvedAmount()`（含兜底）之上，于是把量纲错误的估算值当成真实成交额展示 —— 直接违反 **REQ-032**「指数成交额不可得时不得以推测值充当」。
3. **缺失与 0 未区分（1.3）**：`computeTradeArea()` 只在「窗口内从未交汇」时返回 `null`；当所有交易日的成交额都不可得时，求和结果为 `0` 并被原样返回，于是 `formatTradeArea()` 显示 `0.00亿`（仅追加「覆盖不完整」），违反 REQ-026/030 第 ⑤ 条铁律。

## 3. 修复

| 位置 | 修复 |
| :--- | :--- |
| `web/app.js` `generateDailyKlineSVG` | 副图「总和」改读 `windowAmount.totalAmountYi`，`days > 0` 才出数；含估算样本时显式追加「（含估算）」；表格汇总同口径修正 |
| `web/app.js`（死代码） | 删除从未渲染且字段名错误的 `subSumBadge` 块，避免后续优化者误判「总和」已有实现 |
| `web/app.js` 新增 `indexDisclosedAmountSamples()` | 需求REQ-032 专用口径：**只采信来源原始披露的成交额**，`resolveKlineAmount` 标记为 `derived` 的估算值整段剔除 |
| `web/app.js` 指数副图 | 四维分布改为建立在 `indexDisclosedAmountSamples(klines)` 之上；无样本时如实输出「当前来源未披露该指数成交额，四维分布不可得（不以点位×成交量推测值充当）」 |
| `web/app.js` 指数副图刻度 | `maxAmount` 只取来源披露样本；无样本时刻度文案显示「不可得」，不再使用伪造的 `0.1亿` |
| `web/app.js` `computeTradeArea` / `attachTradeAreaToLines` | 新增 `disclosedOnly` 选项；指数辅助线（自动线与手动线）一律按该口径计算交易面积 |
| `web/app.js` `computeTradeArea` | 整段区间成交额全部不可得时返回 `tradeAreaYi: null` 并给出原因，由 `formatTradeArea()` 显示「交易面积: 未交汇」，不再以 `0.00亿` 冒充 |

## 4. 验证

- 静态用例 `tests/test_r09_subplot_header.js`：
  - `indexDisclosedAmountSamples()` 对「仅成交量+价格」的指数样本返回**空数组**（估算值被剔除），对真实 `amount_yi` / 来源 `amount` 保留；
  - `computeTradeArea(..., {disclosedOnly:true})` 的 `tradeAreaYi === null` 且 `reason` 含「未披露」，`formatTradeArea()` 输出 `交易面积: 未交汇`；
  - 成交额副图「总和」等于窗口内样本之和（构造 30 根 → `总和: 34.35亿`，不再是 `--`）；全估算样本 → `总和: …亿（含估算）`。
- 真机（`tests/browser_r09_verify.js`，28/28 PASS，证据 `docs/verification/2026-09-24-r09/`）：
  - 指数副图刻度实测由 `3943379.8亿` 变为 `不可得`；
  - 指数副图四维分布实测为「不可得」如实标注，且页面内不再出现 `0.00亿`；
  - 个股日K成交额副图实测 `总和: 1098.74亿（含估算）`，表头 `getBBox()` 零重叠、右缘 825.9 ≤ 绘图区右缘 855。

## 5. 预防

1. **字段名与返回值必须成对核对**：读取聚合结果时先看产出函数的 `return` 形状；`undefined` 参与 `Number.isFinite` 判定会静默退化为兜底分支，属于「不报错但显示错误」的高危形态 —— 本次把「是否出数」的判定条件从「字段有限」改为「字段有限 **且** 样本数 > 0」。
2. **指数与个股的成交额口径必须显式分叉**：凡是指数相关的成交额统计/刻度/面积，一律走 `indexDisclosedAmountSamples()` / `disclosedOnly` 口径，禁止把 `resolveKlineAmount()` 的兜底估算值直接用于指数。
3. **「不可得」与「0」必须在类型层面区分**：缺失一律返回 `null`，由展示层翻译为「未获取 / 不可得 / 未交汇」，绝不让 `0` 参与缺失语义。
4. **死代码即隐患**：引用错误字段且从未渲染的代码块会误导后续优化，发现即删除并在台账中登记。
