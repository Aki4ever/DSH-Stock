# BUG-002 历史K线截断

状态：已解决（本地验收）。首次/最近：2026-09-19。任务：R01。需求：REQ-008 v1。提交：待提交。

预期：获取来源可提供的全部日线，展示窗口不截断保存历史。
实际：腾讯请求固定640根，新浪备用固定320根；数据库`ORDER BY date ASC LIMIT 5000`在超限时保留最早数据。缓存非空不刷新，无法补旧历史或后续交易日。

最小样例：腾讯茅台无起止日期返回640条（2024-01-29起）；使用2002年截止日期可读取2001-08-27起的上市行情。SQLite中4条日期记录用limit=2，修复前返回前两条而非最近两条。

方案：按页最早日期的前一天向前翻页，空页才确认为来源已穷尽；去重、排序并验证证券身份/日期/价格/页游标；不以短页判完整；失败或保护上限标partial。默认查询不限制根数，显式limit返回最近N根。默认展示不复权并标明口径、来源、完整性和范围；缺成交额显示未提供，禁止估算成交额冒充真实。

验证：6001根确定性分页测试、短页继续、重复页停止、数据库limit测试。真实茅台6007根、农业银行3928根、平安银行8537根，均到2026-09-18，证据见 [接口核验](../verification/2026-09-19-fix/http-history.json)。来源完整不等同于交易所逐日完整性认证，停牌和来源未收录的交易日不补造。

回退与环境：同BUG-001。防复发：超过5000根、来源异常和刷新恢复回归。
