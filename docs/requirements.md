### REQ-020 v1：策略选股与实时信号预警

  1. **底背驰**：最近 `divergence_lookback`（默认 8）笔内存在笔级底背离。
  2. **放量突破中枢**：最新收盘价站上最近一个**已确认**笔中枢上沿 ZG，突破幅度 ≥ `min_breakout_pct`（默认 0.5%），且**突破发生在底背离之后**；若中枢结束时间早于底背离，判定为「先突破后衰竭」的反向结构并否决。
  3. **放量**：当日成交量 ≥ 前 `volume_window`（默认 20）日均量 × `volume_ratio`（默认 1.5）。
- 结构止损取**中枢上沿 ZG 本身**（跌回中枢之内即代表突破失败）；本策略不臆造目标位，`target_price` 恒为 `null` 并附 `target_note`。
- 每个未命中都给出**具体差距**（当前突破幅度 vs 要求、当前量比 vs 要求、缺哪条判据），便于人工复核；`evidence` 携带判定所用的全部真实数值。
- **数据新鲜度硬约束（新增，关键）**：本策略三条判据都依赖最新交易日，因此当 `fetch_daily_bars` 返回 `stale`（来源不可用、仅剩此前核验过的真实完整历史缓存）时，**明确拒绝判定**并说明原因，绝不用历史某天的结构冒充当日信号。这与 REQ-019 雷达形成有意的差异：雷达做结构解构，允许使用 `stale` 缓存但会标注数据新鲜度与 `last_bar_date`；选股做当日择时，不允许。
- **成交量口径**：只使用可信不复权日线的真实 `volume` 字段；成交额来源未提供即不参与判定，**不用「成交量 × 收盘价」之类的推算值冒充成交额**。前 N 日存在缺失或 0 成交量时直接不判定，不跳过缺失值硬算均量。

### REQ-022：K线视图口径（标准 200 根槽位 + 纯根数缩放）
- **目标**：把 K 线图的「视窗」与「缩放」拆成两件独立的事，消除「缩放即改绘图区宽度」导致的图形跳动。
- **标准情况定义**：首次切换到任一 K 线 Tab（5/10/20/60/120/180/全部）时，视窗固定显示 **200 根**；标的可用 K 线不足 200 根时，显示全部可用根数（**不补造、不重复、不拉伸**）。
- **缩放定义**：放大缩小**只改变同一页面内的 K 线根数**，不改变绘图区尺寸、不改变每根 K 线的显示宽度基准。滚轮向上＝放大（根数减少，最少 5 根），滚轮向下＝缩小（根数增加）。
- **缩放下限**：`5` 根；**缩放上限**：`min(200, 该标的可用 K 线根数)`。即本批**不允许**通过缩放看到超过 200 根。
- **生效范围**：个股详情页全部 K 线 Tab；指数详情页同口径（指数轴上限同为 200 根）。
- **不受影响项**：分时图仍为全天全景、禁用滚轮缩放（维持既有 `需求1` 口径）。
- **验收标准**：
  - [x] 首次切 Tab → 恰好 200 根（可用不足则全部）——浏览器实测 `sh600519` 切「全部」Tab 实绘 200 根；
  - [x] 滚轮缩放前后对比：绘图区左右边界、Y 轴位置不变，只有根数变化——缩放后绘图区左缘/内宽仍为 65 / 730px；
  - [x] 缩放上限严格为 200 根，无法超出——连续 40 次缩小后状态与实绘均为 200 根；
  - [x] 分时图滚轮仍不缩放。

### REQ-023：K线宽度规则（根数不足 200 时右侧留白）
- **单一基准槽宽**：`标准槽宽 = 绘图区内宽 / 200`。个股 K 线绘图区内宽 = `860 - 65(左) - 65(右) = 730px`，故 `标准槽宽 ≈ 3.65px`；指数图沿用其自身内宽同式计算。
- **n ≤ 200**：槽宽固定 = 标准槽宽；蜡烛实体宽度 = `标准槽宽 × 0.72`，以 `x = left + (i + 0.5) × 标准槽宽` 居中绘制。
- **n > 200**：槽宽与实体宽度按 `绘图区内宽 / n` 等比压缩（本批 `n` 最大即 200，此类仅在可用根数超过 200 且未来放开上限时生效）。
- **右侧留白铁律**：`n < 200` 时，**绘图区右侧必须留白且不得以任何方式（拉伸、等比放大、居中铺满、复制）填补**；K 线一律从绘图区左缘开始、向右逐根排列。
- **辅助线不受留白影响**：水平辅助线（自动多阶线／压力线／支撑线）仍绘制贯穿整个绘图区宽度；尽头的标签徽章仍贴绘图区右缘；气泡标注的横坐标仍使用全宽。留白只影响蜡烛与副图柱的横向位置。
- **副图一致性**：成交量／成交额柱与主图 K 线**共用同一槽位与宽度基准**，不得两根图各自居中。
- **验收标准**：

### REQ-024：分时图自动画线 + 缠论画线
- **数据映射**：分时的每个分钟点视为 1 根 K 线 —— `open = close = high = low = price = 该分钟成交价`，`date/time = 该分钟时间`。
- **复用算法**：直接复用既有的自动多阶线引擎（`calculateAutoSupportResistanceLevels`）与缠论叠加渲染（`generateChanlunOverlaySVG`），**不为分时另起一套算法**。分时缠论数据由 `GET /api/stock/<code>/intraday-chanlun` 提供，端点内部同样复用 `scripts/chanlun_analysis.analyze_bars`（同一套算法，仅做「分钟点→K线」的输入映射，前端不含第二套缠论实现）。
- **缠论在分时上的级别口径（须在前端显式说明）**：分时级别下缠论笔＝分钟级笔，**不等于日线级别**；因此分时图的缠论图层（笔／线段／笔中枢／背离／均线缠绕）必须标注为「分时级别」，避免与日线信号混读。
- **渲染位置**：分时图与 K 线图**共用同一套图层模型与同一套图层管理面板**，各图层可独立显示/隐藏、独立清除（延续 REQ-014 口径）。

### REQ-025：成交额缺失兜底（均价 × 成交量）
- **口径变更说明**：本条**明确放宽** REQ-014 中「禁止按 volume×close 推造成交额」的限制，改为允许**有来源标记的兜底估算**；但**真实成交额优先**这一原则不变，且**兜底值必须可区分、可标注**，不得与真实值混为一谈。
- **取值优先级**（逐级降级，前一级取到即停止）：
  1. 来源直接提供的 `amount_yi`；
  2. 来源提供的原始 `amount`（元）→ `amount / 1e8` 折算为亿元；
  3. 兜底推导：`成交额(亿元) = 当日均价 × 当日成交量 / 1e8`。
- **均价定义**：
  - 日 K：`日均价 = (开 + 收 + 高 + 低) / 4`；
  - 分时：`均价 = 该分钟 avg_price`；缺失时退化为 `= 该分钟 price`；
  - 成交量单位按来源口径换算（来源为「手」时先 ×100 得股数，再乘均价并除以 `1e8` 得亿元）。
- **来源标记（强制）**：凡使用第 3 级兜底的数据，须在数据结构上带 `amount_derived = true`，并在**图例／副图标题／辅助线标签**上以固定后缀标注「（估算：均价×成交量）」，让用户一眼可辨真实与推导。副图切换为成交量时，成交额兜底口径仍在图上显式标注（不得因切副图而失去标注）。
- **仍不可得时**：连均价或成交量也缺失 → 该根 K 线 `amount = null`，该周期**不生成自动多阶线**并沿用 `autoLinesBlockedReason` 显式说明原因；**禁止以 0 参与排序或求和**。
- **验收标准**：
  - [x] 真实 `amount_yi` 存在时，结果与既有实现逐位一致（兜底不介入）——单测断言真实值与原始 `amount` 两级均 `derived = false`；
  - [x] `amount_yi = null` 但 volume 可得时，日 K 也能生成自动线，且标记为估算来源——浏览器实测 200/200 根来源缺成交额时仍生成 2 根自动多阶线且全部标记估算；
  - [x] 均价与 volume 均缺失时，仍严格不生成自动线，且原因可见——`autoLinesBlockedReason` 含缺失根数与兜底失败原因；
  - [x] 估算值与真实值在同一面板中可区分（带后缀标注）。

### REQ-026：辅助线指标「交易面积」+「!」指标说明入口
- **指标定义**：某条压力线的「交易面积」＝ 从该线**首个与 K 线交汇的交易日**起至**今天（最后一根可用 K 线）**止，**剔除该线自身交汇的那些交易日**后，剩余交易日对应的 K 线**成交额之和**。
- **计算公式（评审用）**：
  ```
  D         = 该线全部交汇交易日集合 { d | low_d ≤ P ≤ high_d }
  d_first   = min(D)                     // 无交汇 → 交易面积无定义，显示「未交汇」
  T         = { d | d_first ≤ d ≤ 今天 }
  S_area(P) = Σ amount(d)   for d in (T \ D)
  ```
  其中 `amount(d)` 取值优先级与兜底口径见 REQ-025。
- **口径铁律（三条）**：
  1. 是「首个交汇日 → 今天」的**累计**口径，**不受当前缩放窗口影响**（缩放到 5 根时该值不变）；
  2. **必须剔除该线自身交汇的交易日**（只统计「没在压力线上的 K 线」）；
  3. K 线不足（T 内存在 `amount` 不可得的交易日）时，在展示处**显式说明覆盖不完整**，不得以 0 补齐、不得静默出数。
- **适用范围**：`auto`（自动多阶线）／`manual_up`（压力线）／`manual_down`（支撑线）全部辅助线模型，统一同一算法。
- **展示位置（三处，必须数据同源）**：
  - 图内辅助线标签徽章：现有「交汇: X亿, 交易日: N天」之后追加「交易面积: X.XX亿 (未交汇: M天)」；
  - 图层管理面板该模型行的指标摘要；
  - 未交汇状态的提示同步显示「交易面积: 未交汇」。
- **「!」指标说明按钮（本批新增控件）**：
  - 位置：**水平辅助线模型面板的标题行旁**（`📏 水平辅助线模型……` 之后），个股与指数两个面板均已挂载（`btnLineMetricHelp` / `btnIndexLineMetricHelp`），与既有「📖 适用范围」属同一交互族（单击弹出说明弹窗）；
  - 内容至少覆盖：① 交汇成交额；② 交汇交易日天数；③ **交易面积（含上述公式与三条口径铁律）**；④ 成交额兜底口径（REQ-025，含「估算：均价×成交量」标记的含义）；⑤ 自动多阶线的排序与「交汇交易日集合互不重复」约束；⑥ 数据不足时的展示规则（为什么显示「未获取/无法测算」而不是 0）；
  - 样式沿用既有 `modal-overlay` / `modal-content` / `btn` / `chart-layer-btn` 谱系，不新造并列样式族（REQ-018 横切约束）；
  - **与交易面积指标同一批次交付**：公式说明的可见性与指标上线不可拆分。
- **验收标准**：
  - [x] 图层面板标题旁存在「!」按钮，可点击打开说明弹窗，弹窗内含交易面积公式原文与三条口径铁律；
  - [x] 手动画一条压力线 → 标签出现「交易面积」且数值 = 首个交汇日至今非交汇日成交额之和——浏览器实测以全量 6007 根 K 线独立手算比对，两条自动线逐条一致（83434.80 亿 / 82527.03 亿）；
  - [x] 缩放窗口从 200 根改到 5 根，同一条线的交易面积数值**保持不变**；
  - [x] 指数详情页同口径：首次切「全部K线」实绘 200 根，连续缩小后仍被夹取在 200 根，首根左缘 / 占用宽度 / 单根宽度缩放前后逐位不变。
  - [x] 该线从未交汇时显示「未交汇」而非 0；
  - [x] 使用 REQ-025 兜底成交额时，标签带「估算」标记；

### REQ-040 缠论判定口径（验收依据，不得放宽）
| 标记 | 判定定义（本工程实现口径） |
| :--- | :--- |
| 第一类买点 | **趋势**（两个同向且互不重叠的连续中枢，后一中枢完全位于前一中枢下方）中，**最后一个中枢的离开段**相对该中枢的**进入段**出现趋势背驰：价格创新低 **且** MACD 绝对柱面积缩小。项目 `RULES` 已声明「笔背离 ≠ 完整趋势背驰」，故**禁止**用单笔背离冒充第一类买点。 |
| 第二类买点 | 第一类买点之后的**第一次次级别回调**（第一笔向下笔）**不创新低**（回调低点 > 第一类买点低点）。 |
| 第三类买点 | 中枢结束后**向上离开中枢**，随后的**回调不重新回到中枢区间**（回调低点 > 中枢上沿 ZG）。 |
| 第一类卖点 | 对称：上涨趋势（后一中枢完全位于前一中枢上方）中最后一个中枢的离开段创新高且 MACD 面积缩小。 |
| 第二类卖点 | 第一类卖点之后第一次反弹不创新高。 |
| 第三类卖点 | 向下离开中枢后反抽不回中枢（反抽高点 < 中枢下沿 ZD）。 |

**诚信与可复算约束**：判定只使用该点及其之前的数据（**无未来函数**，截断重算后历史点位逐条一致）；点位价格必须等于该根K线的**最低价**（买点）/**最高价**（卖点），绝不凭空生成价格；识别不到即为 0，按钮上如实标注识别数量，未获取缠论分析的颗粒度（周线/季线/分钟K线）标注「未获取」并**不渲染任何标记**；每个标记的悬停提示必须给出判定依据（中枢上下沿、进出段价格、MACD 面积等）。

### R09 顺带修复的真实缺陷（如实登记）

1. **「总和」恒显示 `--`**：副图成交额档与表格汇总读取的是不存在的字段 `windowAmount.totalYi`，而 `computeWindowTotalAmount()` 返回的字段是 `totalAmountYi` —— 成交额明明可得却长期显示 `--`。已按同一解析口径改为读取 `totalAmountYi`，并在含估算样本时显式追加「（含估算）」。
2. **指数副图出现量纲错误的天文数字**：指数来源未披露成交额时，四维分布/副图刻度/交易面积原先把「指数点位 × 成分股成交量」的兜底估算值当成交额使用，实测得到 `3,943,379.8亿`（与真实全市场成交额相差数千倍）。已按 REQ-032 新增 `indexDisclosedAmountSamples()` 与 `computeTradeArea(..., {disclosedOnly:true})`，估算值整段剔除，改为如实标注「四维分布不可得」、刻度显示「不可得」、交易面积显示「未交汇」。
3. **「不可得」被当作 0 展示**：`computeTradeArea()` 在整段区间一段可用成交额都没有时仍返回 `0.00亿`，与「面积为 0」是截然不同的结论。现改为返回 `null` 并给出原因，由 `formatTradeArea()` 统一显示「未交汇」。
