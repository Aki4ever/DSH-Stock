## 一、需求简化文案（执行版）

> **总口径**：需求 1、2 属「既有能力补漏 + 语义收紧」，需求 3 属「REQ-098 遗漏行补齐」。三项全部落在 `web/` 前端，服务端零改动、行情取值口径零变更。

### REQ-099 · K线图左右滑动平移（日线 / 周线 / 季线全覆盖）
- **物理定义**：在 K 线面板主图区域横向拖动（鼠标左键拖拽 / 移动端单指横滑），视窗沿时间轴平移 —— **右滑看更早历史、左滑看更新走势**；到最早/最新一端即钳制停住。
- **必须成立**：① 三个 Tab（日/周/季）切换后手势仍生效（切 Tab 会重建 SVG，绑定不能丢或重复）；② **一次手势只平移一次**（`window` 监听器不得随重绘累加，否则「越滑越快」）；③ 平移不得误触发「点击画水平辅助线」，纵向手势归页面滚动。
- **边界**：当日分时图**不参与**横向平移（固定全天全景）。

### REQ-100 · ± 按钮 同源 · 同量级 · 严格可逆
- **物理定义**：`➕` 与 `➖` 共用**同一步长来源**，步长由**固定锚点**算出唯一**整数**值；`➕` 后立即 `➖` 必须回到**原值**（需求方原话：47 → 40 → 47）。
- **必须成立**：① 步长必须取整（分数步长会让回程丢根）；② 正反步长必须相等（旧算法按当前值取 15%，正是 47→40→46 的根因）；③ 上下限仍为 30 根 / 该颗粒度全部可用根数（个股 200 封顶）；④ 作用域覆盖左右两面板浮动 ± 与指数页滚轮缩放。

### REQ-101 · 副图底部信息条文字放大一倍
- **物理定义**：副图底部那一行（左下「总成交额 / 区间累计换手率」＋ 右下「⚠️ 其中 N 根成交额为估算…」）字号 **10 → 20**，与表头 `SUBPLOT_HEADER_FONT_SIZE` 同源同值。
- **必须同时成立**：① **不得被裁切**（基线原为「副图底 + 11」，是按 10px 设计的，放大后下缘会越出 viewBox）；② 不得压副图柱、不得与表头重叠；③ 文案/口径/颜色/对齐策略一律不变。

## 四、原始需求（用户原话，保留可追溯）

1. K线图中的日线图、周线图、季线图可以对 k 线图进行左滑和右滑手势从而对 K 线图左滑右滑的操作；
2. +- 按钮每次都应该是同样水平的操作，例如 + 之前是 47 列，+ 之后是 40 列，那么再 - 也应该是 47 列；+- 应该同源以及同数量级；
3. 如图 3 中红框内的文字也应该放大一倍。
